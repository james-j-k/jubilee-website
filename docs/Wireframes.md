# Wireframes

## Wireframe conventions

These diagrams define hierarchy and behavior, not final visual styling. `[]` indicates a control; horizontal rules indicate intentional content separation. Each block is included only where it advances orientation, confidence, comprehension, or conversion.

## Home — desktop

```text
┌──────────────────────────────────────────────────────────────────────┐
│ BRAND    Home About Services Commercial Safety             [Contact]  │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│ Reliable LPG delivery.                         Product-quality       │
│ Trusted by thousands of families.              visual / image        │
│ Supporting statement.                                                │
│ [Contact us]   View services →                                      │
│                                                                      │
├──────────────────────────────────────────────────────────────────────┤
│  Request ───── Coordinate ───── Continued support                    │
├──────────────────────────────────────────────────────────────────────┤
│ Service heading                                                    → │
│ [service card]       [service card]       [service card]             │
├──────────────────────────────────────────────────────────────────────┤
│ Commercial story / benefit                 [Supporting visual]       │
│ [Start an enquiry →]                                                │
├──────────────────────────────────────────────────────────────────────┤
│ Safety gateway                                [Contact panel]        │
└──────────────────────────────────────────────────────────────────────┘
```

Desktop uses space to create composure, not to introduce more content. The split hero gives the promise and visual equal importance; downstream sections use grids only where comparison benefits from them. The thin energy line connects the approved Reliability System sequence, making the visual signature functional: it explains continuity from request through support. A verified evidence module may appear after the sequence only when approved; it is not shown as a mandatory testimonial strip.

```text
│ Header                         │
├────────────────────────────────┤
│ Eyebrow                        │

├────────────────────────────────┤
│ Primary information block       │
│ [Optional supporting image]     │
├────────────────────────────────┤
│ Focused supporting blocks       │
├────────────────────────────────┤
│ Need help? [Contact us]         │
├────────────────────────────────┤

```

The repeatable page template creates familiarity across the site. It leaves room for route-specific content but preserves a consistent closing conversion point.

## Contact — mobile

```text
┌────────────────────────────────┐
│ Contact us                     │
│ The right next step, clearly.   │
│                                │
│ Call / support details          │
│                                │
│ Name       [________________]  │
│ Phone      [________________]  │
│ Enquiry    [________________]  │
│ Message    [________________]  │
│                                │
│ [Send enquiry]                  │
│ What happens next               │
└────────────────────────────────┘
```

Direct contact details precede the form because a form should not be the gatekeeper for a basic service conversation. The form is intentionally short: it exists to route an enquiry, not collect a customer profile.
